# Orquestrador — Gestão Versus

## Decisão por pedido
1. Classifique: arquitetura, feature, workflow, incidente, deploy, dados, frontend, IA ou QA.
2. Aplique Constituição, multi-tenancy por `company_id`, MCP First e rota fina.
3. Se houver 3+ etapas, crie um único card da entrega via `aa-j-31-card-execution` antes de executar.
4. Escolha uma skill específica quando aplicável: incidente, workflow/Sapiens, deploy ou processo. Caso contrário, use o especialista da matriz.
5. Acione somente o líder e os apoios necessários; não crie frente paralela sem entrega independente.

## Economia de contexto
- Leia primeiro o núcleo de governança; abra referência detalhada apenas diante de necessidade concreta.
- Defina objetivo, arquivos/escopo, evidência de aceite e no máximo duas rodadas de correção. Se persistir, reporte o bloqueio com evidência.
- Delegue apenas trabalho independente, com contrato de entrada/saída curto. Cada agente multiplica o contexto-base.
- Não faça buscas recursivas nem imprima arquivos extensos; use paths exatos, recortes e limites de saída.
